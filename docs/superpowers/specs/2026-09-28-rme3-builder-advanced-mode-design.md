# RME3 Module Builder — advanced mode (React views via ZIP) and developer guide

Date: 2026-09-28
Status: Approved design (product owner, Module Builder session)
Builds on: architecture spec §23 "Builder-managed versus Advanced"

## 1. Goal

A module built with the Builder can be downloaded as ZIP, extended with
custom React views (CUSTOM kind + `components/`), and uploaded again —
safely and with documentation in the ZIP itself.

## 2. Pieces

1. **Developer guide in every package**: `compileModule` emits
   `GUIA_DESARROLLO_RUNLY.md`, personalized with the module key, slug,
   entities and their API paths. Contents: workflow (download → edit →
   upload), advanced-mode warning, CUSTOM view recipe (view file,
   `components/index.js` registry, component, navigation), component props
   (`token`, `companyId`, `apiBaseUrl`, `navigate`, `moduleKey`), calling the
   module API with `buildApiHeaders`, available libraries with **real
   versions** (shared vs bundled), import rules, Runly design rules.
2. **Runtime catalog**: `packages/module-compiler/src/runtime-catalog.json`,
   generated by `scripts/generate-module-runtime-catalog.mjs` from the
   versions installed for `apps/desktop` and the bundler's `BUNDLE_EXTERNALS`.
   A test fails when the catalog drifts from either.
3. **CUSTOM components receive `apiBaseUrl`** (BlueprintCrudScreen).
4. **"Convertir a modo avanzado"** in the Builder editor (menu, ConfirmDialog)
   calling the existing `POST /module-builder/projects/:id/detach`.
5. **Auto-detach on upload**: `POST /modules/:key/upload` of a package that
   changes the installed code (`outcome !== 'NO_CHANGES'`) detaches the
   module's Builder project, so a later Builder publish can never overwrite
   hand-written code. The response carries `builderDetached: true` and the UI
   says so.

## 3. Out of scope

Code → Builder round-trip (no re-import of edited packages into the visual
editor), TypeScript in module bundles, editing code inside Runly.
